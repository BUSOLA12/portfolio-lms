Design system · v1.0

Green & Ochre

One visual language for two jobs: a portfolio that shows the work, and a learning platform where students move through it.

01

How to use this

Two layers. Primitives are raw values — --green-600, --space-5. Semantic tokens describe a job — --action-primary-bg, --state-done-text. Components reference semantic tokens only. When you rebrand, you edit one layer and everything follows. "Primitive" means a raw token value and nothing else — the shared component layer (Button, Input, Card, Badge, Rail) is called elements, so the two words never collide.

/* Wrong — locks the colour into the component */
.enroll { background: var(--green-600); }

/* Right — states the intent */
.enroll { background: var(--action-primary-bg); }
02

Colour

Green is the workhorse — navigation, links, primary actions, inverse sections. It is deep and forest-toned rather than eco-bright, which keeps it reading as considered rather than as a sustainability brand. Ochre is rationed: one per screen region, marking the single next thing to do. Green also carries the done state, so green consistently means progress. Red is reserved for overdue, never decoration.

Space & shape

4px base. Steps 1–4 for inside components, 5–7 between components, 8–11 between page sections. Radius climbs with the size of the thing: 6px on buttons and inputs, 16px on cards, full only on badges and avatars.

05

Actions

Green is the default primary. Ochre appears once per region, on the action you actually want taken — enrol, continue, start. If two ochre buttons are visible at once, one of them is wrong.

We use this for your login and course updates. Nothing else.

06

Status vocabulary

Four states, and only four. Every tranche, class session, assignment and payment is exactly one of them. Students learn the colours once and read them everywhere.

07

Signature: the stepped rail

The one motif this system is remembered by. Diamond knots on a vertical rail, filling as you advance. In the LMS it's tranche progress. On a project page it's the build timeline. Same component, and in both places the order genuinely carries meaning — which is the only reason to number anything.

09

Non-negotiables

Rules that keep the system from drifting once other people start building in it.

  • Components never reference a primitive. Semantic tokens only.
  • "Primitive" means a raw token value. The shared component layer is elements, in components/elements/; everything above it is organised by feature.
  • A class session's visual state comes from entitlement and schedule, never watch progress. A paid future class session that is not next up carries no badge — the absence of a state, not a fifth one.
  • One ochre element per screen region.
  • Mono is for code and numbers. Not for emphasis.
  • No fifth status. If something doesn't fit the four, redesign the flow.
  • The visual state active is not the enrollment status. In the database an enrolled learner is enrolled, never active.
  • The stepped rail is the only motif. Don't add a second.
  • Every interactive element has a visible focus ring and a 44px minimum touch target.
  • Body copy stays within 68 characters per line.
